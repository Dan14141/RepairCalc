# RepairCalc

Сервис планирования ремонта по кейсу «Максидома»: React 19 / TypeScript / Vite и Java / Spring Boot. В NOT MOCK каталог, расчёты и проекты обслуживает PostgreSQL; H2 и стартовые товары-заглушки удалены. ML-помощник пока использует правила, обученная модель не подключена.

## PostgreSQL и NOT MOCK

Нужны Docker Desktop, JDK 17+ и Python с зависимостями из `server/requirements-tools.lock.txt`. На текущем ПК образы и локальные секреты уже подготовлены. Команды из корня репозитория:

```powershell
cd server
.\scripts\Start.ps1
.\.venv\Scripts\python.exe scripts/import_maxidom.py products_final.json
cd ../backend/backend_java
.\gradlew.bat build
cd ../../server
.\scripts\Start-Backend.ps1
# Для обновления запущенного бэкенда этого checkout: .\scripts\Start-Backend.ps1 -Restart
```

API: `http://127.0.0.1:8000/api/v1`; PostgreSQL: `127.0.0.1:5433/repaircalc`, схема `repaircalc`. `Start.ps1` применяет миграции и готовит игнорируемый Git файл `server/.secrets/backend.properties`. Spring также принимает `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` из окружения. `ddl-auto=validate` проверяет готовую схему; её изменение выполняется миграциями.

В браузере выберите NOT MOCK и указанный адрес API. 88 790 строк выгрузки сохранены целиком, каталог содержит 88 746 уникальных артикулов. Поиск, сортировка и страницы обрабатываются сервером. Неоднозначные характеристики не превращаются в выдуманные нормы расхода: такие товары доступны в каталоге, но без автоматического расчёта. Подробности и команды проверки: [server/docs/POSTGRES_APPLICATION.md](server/docs/POSTGRES_APPLICATION.md).

## Отправки смет и оценки ИИ

В смете кнопка «Поделиться сметой» открывает предпросмотр текста с материалами,
количеством, ценами, запасом, итогами и предупреждениями. Доступны системное меню
отправки (если его поддерживает браузер) и копирование в буфер обмена.
При переходе на второй этап, после загрузки подбора, в углу появляется небольшое
окно «Как Вам подбор?» со звёздами 1–5 и крестиком. Оценка отправляется сразу
нажатием на звезду; окно можно закрыть или игнорировать, продолжая расчёт.
После успешного сохранения благодарность скрывается автоматически через 2 секунды.

В админке, во вкладке «Метрики успеха», блок «Отправки смет и оценки ИИ» показывает
отправки, уникальные браузеры, число оценок, среднюю оценку и распределение по звёздам.
Это накопленные действия за всё время, с даты первого события; период демонстрационного
отчёта выше к ним не относится. Отмена и ошибки копирования не учитываются.
Уникальность определяется анонимным идентификатором браузера, а не учётной записью.
В MOCK события хранятся локально, в NOT MOCK — в PostgreSQL (`005_engagement.sql`).
Повтор запроса с тем же идентификатором события не увеличивает счётчики.

Новые e2e-сценарии находятся в `frontend/tests/engagement.spec.ts`. Для полного прогона
с локальным PostgreSQL после запуска `server/scripts/Start.ps1`, сборки Java и запуска
`server/scripts/Start-Backend.ps1`:

```powershell
cd frontend
$env:LIVE_API_URL = 'http://127.0.0.1:8000/api/v1'
$env:LIVE_ENGAGEMENT_E2E = '1'
npm.cmd test
```

`engagement-live.spec.ts` проверяет реальный буфер обмена, запись событий и метрики
через HTTP. Он рассчитан только на локальный backend на порту 8000 и Docker Compose
этого checkout; после проверки удаляет только собственные события по их UUID.
Остальные тесты можно запускать без этих переменных и без сервера.

## Запуск

Требуется Node.js 22.12+.

```bash
cd frontend
npm install
npm run dev
```

Сайт откроется по адресу **http://127.0.0.1:4173**. В Windows PowerShell с ограничением запуска `.ps1` используйте `npm.cmd install` и `npm.cmd run dev`.

```bash
npm run build    # Проверка TypeScript и production-сборка в dist/
npm run preview  # Просмотр production-сборки
npm test         # Проверки сценариев в Chromium
npm run format   # Форматирование исходников
```

Для тестов нужен браузер Playwright: `npx playwright install chromium`. На рабочем компьютере тесты также умеют использовать уже установленный Chromium. Если порт 4173 занят, запустите `npm run dev -- --port 4174`.

## Что работает

- **Калькулятор из трёх этапов.** Объект, тип ремонта, несколько помещений, длина, ширина, высота, окна и двери, влажность и нагрузка. Схематичный план комнаты изменяется вместе с размерами.
- **Материалы.** Три варианта комплектации и ручная замена напольных и настенных покрытий. Для влажных помещений и высокой нагрузки выбор ограничивается подходящими характеристиками.
- **Умный помощник.** Описание комнаты → извлечённые параметры и предположения → редактирование и подтверждение. ML-рекомендации учитывают контекст комнаты, показывают альтернативы, причины выбора и справочные источники.
- **Админка.** Отдельный пункт в блоке «Для персонала», вкладки «ML-мастерская» и «Метрики успеха». Ссылки на вкладки сохраняются при перезагрузке, работают история браузера и переключение клавиатурой. Старый адрес `#matching` открывает `#admin/matching`.
- **ML-мастерская в админке.** Выбор товаров, сопоставление с несколькими видами работ и помещений, проверка объяснений, ручная корректировка, подтверждение и отклонение привязок.
- **Метрики успеха.** Precision / recall / F1 по топ-категориям с целью MVP F1 ≥ 0,8, MAE расхода по единицам материалов, доля автоматических привязок, среднее время сметы и P95, клики до корзины, доля завершённых сценариев и ошибок запросов. Есть период, версия модели, сведения о выборке, методика и обновление отчёта. В MOCK используется явно подписанный демонстрационный отчёт; в HTTP — `GET /admin/metrics`. Отсутствующие наблюдения показываются прочерком.
- **Тестовый режим.** Плавающая кнопка в правом нижнем углу переключает весь фронтенд между MOCK и NOT MOCK. В панели настраиваются адрес API, задержка заглушки, ошибка / пустой результат ML и виден журнал запросов. При ошибке сервера скрытого возврата к заглушкам нет.
- **Смета.** Количество упаковок, разбивка по категориям и помещениям, запас 5/10/15%, отдельная ориентировочная стоимость работ. Экспорт CSV с UTF-8 BOM для Excel; PDF — через диалог печати браузера.
- **Каталог.** Поиск, фильтры, сортировка, избранное. В карточке товара — интерактивный расчёт количества и цены по площади, выбор покрытия для текущей комнаты.
- **Мои проекты.** Создание, переименование, копирование, поиск и удаление. В MOCK проекты и избранное сохраняются локальным адаптером в `localStorage`, в NOT MOCK — через HTTP API. Сохранения последовательны; ошибки можно повторить без потери текущей правки.
- **Справочник.** Статьи о замерах, запасе материалов, влажных помещениях и выборе покрытий.
- **Адаптивность.** Макеты для телефонов, планшетов и широких экранов, отдельная навигация на мобильных устройствах.
- **Доступность.** Клавиатурная навигация, управление вкладками стрелками, удержание и возврат фокуса в диалогах, Escape, подписи полей, уменьшение анимации и контрастный текст.

## Границы демонстрационного расчёта

В MOCK товары, цены, рейтинги, ML-оценки и нормы расхода — **иллюстративные данные**, а не выгрузка действующего магазина и не результат запущенной модели. Шрифты и графика локальные, без CDN. В NOT MOCK каталог, сметы и ML-ответы приходят от настроенного сервера.

- Пол: `длина × ширина`.
- Стены: `2 × (длина + ширина) × высота − окна × 2,1 − двери × 1,6`, минимум ноль.
- Количество: `ceil(площадь × (1 + запас / 100) / полезная площадь упаковки)` отдельно для каждой комнаты. Полезная площадь краски уже учитывает два слоя; обоев — принятую в демонстрации полезную площадь рулона.
- Для капитального и дизайнерского ремонта добавляются штукатурка и розетки; грунтовка включена всегда. Во влажной комнате используется цементная штукатурка и пример розетки IP44.
- Работы: условно 900 / 1 800 / 2 800 ₽ на м² для косметического / капитального / дизайнерского ремонта.
- Мебель и расположение проёмов на плане схематичны. Сложная геометрия, электропроект, гидроизоляция, клей, крепёж, доставка, демонтаж и точная технология работ требуют отдельного расчёта.

Эти формулы реализованы внутри мокового адаптера. UI обращается к одним и тем же типизированным методам в обоих режимах. В NOT MOCK результаты расчётов не вычисляются на данных заглушки. Для валидации полей, плана и ограничений материалов остаётся обычная клиентская логика.

## Подключение сервера

Откройте «Тестовый режим», задайте базовый адрес (включая `/api/v1`) и выключите переключатель MOCK. По умолчанию используется `http://127.0.0.1:8000/api/v1`; начальное значение можно задать через `.env` по образцу `.env.example`. Сохранённая настройка в интерфейсе имеет приоритет.

Сервер находится в `backend/backend_java`. Контракт описан в [frontend/docs/api-contract.md](frontend/docs/api-contract.md); серверный каталог дополнительно доступен по `GET /catalog?search=&category=all&sort=recommended&page=0&size=48`. Цены приходят из предоставленной выгрузки, синхронизация с текущим каталогом магазина не выполняется.

Админка в этой демонстрации отделена навигацией; авторизация и ограничение доступа по ролям ещё не реализованы. Перед использованием с реальными данными сервер и клиент должны обеспечить доступ персонала. Сбор аналитики и событие готовой корзины также должны поступать из интеграции: просмотр сметы и экспорт CSV не подменяют корзину, ручное подтверждение привязки не считается автоматической разметкой.

NOT MOCK при недоступном сервере показывает ошибку подключения и кнопку повтора. Моковые проекты при этом остаются отдельно и восстанавливаются после включения MOCK.

## Структура

```text
src/
  App.tsx          — страницы, состояния проекта и пользовательские сценарии
  components.tsx   — диалоги, поля, переключатели, план и интерьерная SVG-графика
  data.ts          — типы, демонстрационный каталог, формулы и локальное хранение
  services/
    contracts.ts   — DTO и интерфейс общего API
    client.ts      — HTTP-клиент, маршрутизация MOCK/HTTP и проверка ответов
    mock.ts        — локальный адаптер, данные и воспроизводимые ML-ответы
    runtime.tsx    — настройки, плавающая панель, загрузка и сохранение
    selection.ts  — клиентские ограничения выбора материалов
  ml/
    Assistant.tsx  — описание комнаты, рекомендации и объяснения
    Matching.tsx   — проверка и редактирование ML-привязок
    ml.css         — стили ML-экранов и тестовой панели
  admin/
    Admin.tsx      — вкладки ресурсов персонала и маршруты
    SuccessMetrics.tsx — отчёт о метриках, цели и методика
    admin.css      — адаптивные стили админки
  styles.css       — компоненты и основная визуальная система
  responsive.css   — адаптивные размеры, печать и уменьшение анимации
  theme.css        — семантические цвета и доступность
tests/
  app.spec.ts      — интеграционные проверки пользовательских сценариев
  ml-runtime.spec.ts — ML-сценарии, HTTP-транспорт, изоляция режимов и ошибки
  admin.spec.ts    — вкладки, метрики, HTTP-ошибки, пустые данные, адаптивность и axe-core
scripts/
  visual-check.mjs        — снимки страниц и проверка горизонтального переполнения
  accessibility-check.mjs — проверка калькулятора через axe-core
  ml-visual-check.mjs     — ML-экраны, мобильные размеры и доступность
  prepare-cache.cjs       — вспомогательная установка из локального npm-кеша
```

`prepare-cache.cjs` нужен только для ограниченного Windows-окружения без доступа к сети; обычная установка выполняется через `npm install`. Скриншоты и временные материалы проверок помещаются в `.cache/`, отчёты Playwright — в `test-results/`; эти каталоги исключены из Git.

## Основа дизайна

Тёплая бумажная поверхность, глубокий зелёный цвет навигации и терракотовый акцент. Manrope используется для заголовков и крупных чисел, Golos Text — для интерфейса. Собственная SVG-графика и CSS-образцы материалов поддерживают архитектурный характер проекта. Пояснения к расчёту находятся рядом с изменяемыми параметрами, а смета остаётся доступна на каждом этапе.
