# PostgreSQL для приложения

Ветка: `test/database-expr`. Основная база приложения — PostgreSQL 17.11 в существующем Compose-проекте `repaircalc-db`. H2 и Java DataInitializer удалены. Hibernate проверяет схему, но не создаёт и не перезаписывает её.

## Запуск

Из `server/`, где уже подготовлены `.venv` и `.secrets`:

```powershell
.\scripts\Start.ps1
.\.venv\Scripts\python.exe scripts/import_maxidom.py products_final.json
cd ../backend/backend_java
.\gradlew.bat build
cd ../../server
.\scripts\Start-Backend.ps1
```

Для обновления бэкенда после сборки: `scripts/Start-Backend.ps1 -Restart`. Скрипт проверяет принадлежность процесса текущему checkout и запускает Java скрыто. Логи находятся в `.cache/` корня репозитория. Альтернатива для разработки: `./gradlew.bat bootRun` из `backend/backend_java`.

Фронтенд: `npm.cmd run dev` из `frontend/`; URL `http://127.0.0.1:4173`. В панели тестового режима задайте NOT MOCK и API `http://127.0.0.1:8000/api/v1`. Сохранённая настройка браузера имеет приоритет.

Пароль берётся из игнорируемого `server/.secrets/backend.properties`, который `Start.ps1` формирует из имеющихся локальных учётных данных. Файлы `.secrets`, `secret data.txt` и исходная выгрузка исключены из Git. Пароль не передаётся аргументом командной строки. Для другого сервера можно задать `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` окружением.

## Данные и расчёты

Миграция `004_application_catalog.sql` добавляет журнал `maxidom_import`, неизменённые исходные строки `maxidom_raw_product`, каталог `products` и проекты/избранное `app_workspace`.

- Источник: 88 790 записей; 88 746 уникальных артикулов `cod_good`.
- У 44 артикулов две строки. В каталоге выбирается первая строка файла; обе версии хранятся в raw-таблице. Такие товары исключены из автоматического расчёта до сверки.
- Импорт атомарный, использует блокировку транзакции и SHA-256 файла. Повторный запуск с тем же файлом не изменяет данные.
- Цена хранится как `numeric(18,2)` / `BigDecimal`, без округления копеек до целых рублей. Расход выражен на единицу продажи из файла.
- 3 352 товара имеют пригодные для расчёта характеристики. У остальных неизвестный расход явно обозначен; API расчёта возвращает 422. Отсутствующий товар — 404, неверные параметры — 400.
- Расход округляется отдельно для каждой комнаты; сумма считается по цене товара. Влагостойкость и износостойкость ограничивают выбор покрытий.
- Если подготовительные материалы не удалось включить, предупреждения отображаются в смете и CSV.

Все товары доступны через серверный поиск/фильтры/пагинацию `GET /catalog`. Bootstrap передаёт только товары с нормами расхода и общее количество каталога. Проекты и избранное сохраняются в JSONB и переживают перезапуск Java и PostgreSQL. Текущее приложение использует одно общее рабочее пространство без пользователей.

Цены относятся к предоставленному файлу, а не к текущему сайту магазина; региональная актуальность не проверялась. У обоев расчёт по площади рулона не учитывает раскрой и раппорт, у штукатурки используется явно указанная толщина 10 мм. Стоимость работ — существующий ориентир приложения, не импортированный прайс подрядчиков. ML-сервис остаётся реализацией на правилах.

## Полная проверка

```powershell
# Из server/
.\.venv\Scripts\python.exe tests/test_storage.py
.\.venv\Scripts\python.exe tests/test_pgadmin_connections.py
.\.venv\Scripts\python.exe tests/test_maxidom_import.py

# Из backend/backend_java/
.\gradlew.bat build --rerun-tasks

# Из frontend/; backend и PostgreSQL должны быть запущены
npm.cmd run build
$env:LIVE_API_URL='http://127.0.0.1:8000/api/v1'
npm.cmd test
```

Java-тесты выполняются с PostgreSQL; изменения тестовых цен и проектов откатываются транзакциями. Проверка импорта сверяет каждую исходную JSON-запись, все артикулы, названия, цены и единицы, а также повторный импорт. Live-тесты браузера используют настоящий API без подмены ответов и не изменяют рабочее пространство. Без `LIVE_API_URL` эти три теста пропускаются, остальные тестируют обычные MOCK/HTTP-сценарии.

Инфраструктурные тесты по умолчанию проверяют локальный pgAdmin. Дополнительные адреса можно явно передать через `PGADMIN_TEST_URLS` (URL через запятую); старый LAN-адрес в тесты не зашит.
